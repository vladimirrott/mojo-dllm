# RTX 6000D Q4_K dispatch measurement

Generated by `python3 bench/report_gpu_dispatch.py`.

Two RTX 6000D GPUs, 156 SMs each, 85,651 MiB, driver 595.104.02; Mojo 1.1.0 (8189361e), max-core 26.6.0, compiled for sm_120. Each model ran on its own GPU, and each A/B pair used the same GPU. Other GPUs on the shared host had existing workloads. No power or clock settings were changed.

Both models use mradermacher Q4_K_M GGUF files. The raw files record their names, byte sizes, GPU identities, source commits and every run. The source URLs were the corresponding Hugging Face repository resolve/main endpoints, accessed through hf-mirror.com on 2026-10-30.

Three prompts, three measured rounds per length; a warmup pair per length is excluded. All runs use 32 forward passes, block length 32, no early stop, threshold or dual cache. These timings cover generation, excluding model startup, and use no synchronizing profiler. Speedup is the median of paired generation-time ratios, not the ratio of the two pooled medians.

## Reproduce

Build the base and candidate commits recorded in `llada.json`/`dream.json` with `MOJO_DLLM_GPU_ARCH=sm_120 scripts/build.sh`. Run the commands in `docs/development.md` under “Comparing GPU dispatch changes”, adding `--lengths 128,256,512,1024` for the full matrix.

The `tiles-*.jsonl` files are the initial synthetic-shape exploration on GPU 5, with fixed-width launches from base 70a0880. Build `bench/bench_gpu_tiles.mojo` with `scripts/build.sh`, then run it with token counts 64, 148, 276 and 532. These batched microbenchmarks include enqueue and synchronization time; they are not a substitute for the paired generation runs. The dispatch wave count is a heuristic, not an occupancy-counter measurement.
